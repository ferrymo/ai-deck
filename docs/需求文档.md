# AI Deck 需求文档

> 版本：MVP v1 · 日期：2026-10-17 · 首发平台：Windows 11 x64

## 1. 产品目标

个人电脑上的 AI 工具管家：自动发现工具，记住安装位置，集中安装、检查更新和按设置自动升级，同时管理个人 skills。用户完成首次设置后，日常专注使用工具。

核心流程：**发现 → 接管或安装 → 保存目录与来源 → 检查更新 → 按策略升级 → 验证结果。**

### 需要特别处理的本机状态

| 状态 | 设计要求 |
| --- | --- |
| Codex 有 npm 安装和桌面应用相关二进制 | 一个产品允许多个安装实例；更新指定实例，不误覆盖其他副本 |
| Gemini 旧 pnpm 入口指向的文件不存在；旧 Claude pnpm 入口也已失效 | 显示“待修复”；Gemini 通过明确的修复/安装操作接管，不能显示为可用旧版本 |
| OpenCode、Ollama 仅发现配置，当前命令未命中 | 显示“仅发现配置”，不计为确认可用安装 |
| Qoder 注册表为 `1.106.3`，EXE 产品版本为 `0.14.2`；部分软件也有不同版本粒度 | 保留原始版本及来源；由产品适配器决定可比较版本，不统一采用 EXE 版本 |
| nvm 当前链接为 `D:\tools\node → D:\tools\nvm\v22.23.1`；npm prefix 指向链接下的 `node_global` | 固定真实 Node、npm、安装目录和子进程环境，避免切换 nvm 后更新错位置 |
| 用户 skills 分布在 `.agents`、`.codex`、`.claude` | 显示宿主、作用域、来源和真实路径，支持多位置管理 |
| 8 个用户 skill 逻辑入口，4 个名称；`find-skills` 有共享 junction；三份 `impeccable/SKILL.md` 内容不同 | 共享目录只更新一次；同名不同内容不自动合并或覆盖 |

其中 `find-skills`、`image-to-code` 的来源锁文件分别记录 `vercel-labs/skills`、`Leonxlnx/taste-skill`，但仍需核对本地基线；其他用户 skills 需要补充来源。插件缓存可能含历史版本，不以缓存文件数作为已启用数量。

## 3. 首版功能

| 模块 | 必须具备的能力 |
| --- | --- |
| 总览 | 展示受管工具、可用更新、失败任务及需要处理的问题 |
| 工具 | 扫描、筛选、查看实例与目录、接管/取消接管、手动检查和升级、设置策略；取消接管保留软件 |
| Skills | 查看来源与宿主、安装、检查/升级、识别共享目录及本地修改、备份和恢复 |
| 商店 | 精选 Codex CLI、Claude Code、Gemini CLI 和已核实来源的 skills；一键安装并记住目录；其他产品明确显示官网引导 |
| 运行时 | 查看 nvm 版本、健康状态、活动版本及工具绑定关系；为受管 npm 工具选择兼容运行时 |
| 任务记录 | 进度、结果、错误原因、重试入口及真实可用的恢复能力 |
| 设置 | 自动升级总开关、各工具策略、检查周期、安装时段、登录自启、通知和代理 |
| 客户端升级 | 后台检查/下载，悬停升级图标查看日志，点击一次自动安装并重启 |

工具能力分别标记为“完整管理”“官方渠道管理”“仅发现/引导”。只有经过适配验收的能力才展示可执行按钮；安装、自动更新、固定版本、恢复分别判断，不互相推导。

## 4. 被管理工具的自动升级规则

1. 提供全局开关和各工具/skill 的独立策略：跟随全局、自动升级、仅提醒、固定版本。默认关闭自动安装；全局关闭时不发起自动安装。
2. 开启后正常升级无需逐次确认。支持每日定时和持续检查；持续模式默认每 30 分钟检查，启动、唤醒、网络恢复时合并补查。
3. “实时”表示后台持续检查，不承诺官方发布后瞬间推送；实际安装遵守用户设置的安装时段。
4. 使用中或文件占用时延后，不终止用户会话；来源不明、本地修改冲突、权限或运行时不兼容时转为“需要处理”。
5. 关窗口后留在托盘继续执行；用户退出 AI Deck 后停止调度。关机/睡眠期间不执行，恢复后补查；登录自启单独设置。
6. 区分 AI Deck、官方自更新、系统商店三个更新执行者。仅提醒/固定版本是否约束官方更新必须显示清楚；不静默修改官方配置。
7. 网络失败显示“检查失败/版本未知”和上次成功时间。失败有限重试，无变化时不打扰；完成、失败或需要操作时通知。

## 5. AI Deck 自身一键升级

目标体验：**发现新版本 → 后台下载并校验 → 图标提示 → 悬停查看升级日志 → 点击一次 → 自动安装并重启。** 正常流程无需用户下载文件、选择目录或二次确认。

- 全局固定位置显示升级图标。下载中显示进度；下载校验完成后提示“更新至 vX.Y.Z 并重启”，此时点击即可升级。
- 鼠标悬停或键盘聚焦图标时显示可滚动日志，包含版本、日期、新增、改进、修复与必要的兼容性说明；跨版本升级可查看跳过版本的变更。
- 点击后若正在执行工具安装任务，自动等待任务结束再更新，显示等待状态，无需再次点击；其他受管工具的使用不被强制终止。
- 安装完成自动重新打开 AI Deck，保留工具清单、设置、任务记录与原页面。重复点击不能启动多个安装器或多个客户端。
- 默认后台检查和下载，安装由用户点击触发；普通退出不自动安装。客户端更新设置与第三方工具自动升级开关独立。
- 下载/校验失败时保持当前版本可用，显示失败原因及重试入口；发布包与发行渠道必须支持正常的一键升级体验。

## 6. 安装、目录与数据保护

- 已有安装沿用原渠道和目录；新安装默认选择兼容运行时及受管目录，允许首次调整。安装器不支持自定义目录时明确说明。
- nvm 仍负责 Node。AI Deck 不通过后台 `nvm use` 更新工具；稳定命令入口按用户选择启用，PATH 与默认命令变更可见。
- skills 来源不明或无法确认初始基线时，先保留现状并提供差异与备份。后续发现本地修改则暂停覆盖；系统、插件缓存不单独替换。
- 凭证和账号留在原工具；安装完成后通过官方入口登录。扫描结果保存在本机，日志脱敏。
- 软件包恢复能力按渠道显示。skills 可恢复文件备份；记录旧软件版本不等于能够完整回滚。

## 7. 交付范围

**P0：** 三类 CLI 安装/修复与自动升级、用户 skills 管理、nvm 运行时绑定、精选商店、托盘调度、任务记录、AI Deck 自身一键升级与悬停日志；本机其他相关工具分类发现和引导。

**P1：** 按验收结果扩展桌面编辑器与 AI 配套工具的安装/升级、受支持渠道的卸载、更多运行时提供者、常用效率工具。

首版不管理项目依赖、虚拟环境、模型权重、Docker/WSL 内部软件、模型密钥或云同步；不提供任意脚本商店，也不建设完整 Node 版本管理器。

## 8. 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 多副本 | Codex CLI 与桌面相关实例分开；只更新选定实例 |
| 目录记忆 | 首次接管/安装后，后续升级不重复选择目录 |
| nvm 切换 | 当前链接变化后，更新仍定位原受管真实目录；不误写另一个版本 |
| 失效入口 | Gemini 旧入口显示待修复；安装后验证真实命令可用 |
| 自动策略 | 关闭不自动安装；开启后正常任务无需逐次确认；定时与持续检查均有效 |
| 后台行为 | 关窗口继续运行，退出停止；恢复后不重复创建同一更新任务 |
| skills | 共享目标只更新一次；来源未知或本地修改不被静默覆盖；备份可恢复 |
| 故障 | 离线、权限不足、文件占用、进程中断均有明确结果，重启后核实并恢复任务 |
| 能力真实 | 未验收的桌面应用不展示自动升级承诺；恢复能力与实际渠道一致 |
| 客户端一键升级 | 下载就绪后点击一次，静默安装并只重启一次；无需选目录，设置、任务和原页面保留 |
| 悬停日志 | 图标悬停/键盘聚焦可查看版本、日期和分类日志；支持滚动、跨版本说明及安全文本展示 |
| 升级协调 | 有安装任务时自动等待后继续，无需再次点击；普通退出不安装，失败不伪报成功 |

技术分层、执行流程和质量要求见[技术实现方案](./技术实现方案.md)。本文记录需求与本机事实，尚未代表安装器或更新流程已实现验证。
